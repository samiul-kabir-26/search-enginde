# Ranking eval — 2026-10-26

Dataset `demo.csv.gz`: 1,000,000 impressions; requests train 16,000 / valid 2,000 / test 2,000 (split by time); 11.6% of impressions have a click, cart or order. Features come from the serving pipeline (`featurejob dataset`); online item features are aggregated as of the end of the training period. Metrics re-rank each test request's logged impressions (graded: order 3, cart 2, click 1).

## Test split (held out) (2,000 requests)

Logged clicks are position-biased (users mostly examine the top), which favours the logged order; compare the rankers with each other.

| Ranker | nDCG@10 | MRR | Δ nDCG@10 vs default_linear at its stage (95% CI) |
|---|---|---|---|
| logged order | 0.4671 | 0.8893 |  |
| default_linear (prerank) | 0.2563 | 0.5231 |  |
| default_linear (rank) | 0.2708 | 0.5293 |  |
| prerank-gbdt-v1 | 0.3348 | 0.6607 | +0.0785 (CI pending rerun) |
| rank-gbdt-v1 | 0.3583 | 0.7006 | +0.0875 [+0.0786, +0.0965] |

## Test split, inverse propensity weighted (position-debiased) (2,000 requests)

Each gain is divided by the examination propensity of its logged position, pos^-0.698 (eta fitted on the training split's randomized requests, weights capped at 10), which removes most of the logged order's advantage from position bias.
